AES Overview & Key Concepts

What is AES?

The Advanced Encryption Standard (AES) is a symmetric block cipher chosen by the U.S. government to protect classified information. It is implemented in software and hardware throughout the world to encrypt sensitive data.

Key Features

  • Block size: 128 bits (16 bytes)
  • Key sizes: 128, 192, or 256 bits
  • Rounds: 10 (128-bit), 12 (192-bit), or 14 (256-bit)
  • Substitution-permutation network architecture

AES Modes of Operation

ECB (Electronic Codebook)

The simplest mode where each block is encrypted independently. Not recommended for most applications due to pattern preservation.

CBC (Cipher Block Chaining)

Each block of plaintext is XORed with the previous ciphertext block before being encrypted. Requires an initialization vector (IV).

CTR (Counter)

Turns a block cipher into a stream cipher. Each block of plaintext is XORed with an encrypted counter value.

GCM (Galois/Counter Mode)

Provides both encryption and authentication. Widely used for secure communications.

AES Challenges & Security Analysis

Challenge 1: Padding Oracle Attack

Explore how improper error handling in decryption can lead to a padding oracle attack against AES-CBC.

In this challenge, you'll interact with a simulated server that decrypts AES-CBC ciphertexts and returns whether the padding is valid or not. Your goal is to decrypt the secret message without knowing the key.

The server uses PKCS#7 padding and will respond with either "Valid padding" or "Invalid padding" for each ciphertext you submit.

Server Response:

Submit a ciphertext to check its padding...

Solution Approach:

  1. Modify the last byte of the second-to-last block and try all 256 possible values.
  2. When the server responds with "Valid padding", you've found a value that creates valid padding (likely 0x01).
  3. Use this to calculate the last byte of the plaintext.
  4. Repeat the process for the second-to-last byte, but now aiming for padding 0x02, 0x02.
  5. Continue until you've decrypted the entire block.
  6. Move to the previous block and repeat.

Challenge 2: Known-Plaintext Attack on ECB Mode

Demonstrate how ECB mode's deterministic nature makes it vulnerable to known-plaintext attacks.

In this challenge, you have access to an encryption oracle that uses AES-ECB with an unknown key. The oracle prepends your input with a secret string before encrypting.

Your goal is to recover the secret string by carefully crafting inputs and analyzing the resulting ciphertexts.

Encryption Oracle Response:

Submit an input to see the encrypted result...

Recovered Secret:

Use the oracle to recover the secret...

Solution Approach:

  1. First, determine the block size (16 bytes for AES) by increasing input length until the ciphertext size jumps.
  2. Confirm ECB mode by encrypting repeated characters and looking for repeated blocks in the output.
  3. To recover the first byte of the secret, send 15 'A's as input. This forces the first byte of the secret into the last position of the first block.
  4. Try all possible values for the 16th byte until you find one that produces a matching first block.
  5. Once found, you know the first byte of the secret.
  6. For the second byte, send 14 'A's and the first recovered byte. Then try all values for the 16th position again.
  7. Continue this process until you've recovered the entire secret.
